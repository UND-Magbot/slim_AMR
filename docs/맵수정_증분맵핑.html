맵 수정과 증분 맵핑

지도에서 검은 장애물을 지워 방해물이 아니게 만드는 기능과, 저장된 지도 위에 이어서 매핑하는 기능. 지운 자리가 어디까지 사라지고 어디는 그대로인지가 설계의 전부다.

01지도는 성격이 다른 두 벌로 저장된다

매핑을 저장하면 한 이름 아래 두 벌이 나온다. 생김새가 아니라 누가 무엇을 읽는가가 다르다.

파일담긴 것읽는 쪽
.posegraph .data 스캔과 스캔 사이의 관계. slam_toolbox 의 원본 자료 slam_toolbox — 위치추정, 이어 매핑
.pgm .yaml 격자지도. 칸마다 비었나 / 막혔나 / 모르나 화면 표시, 자동 위치 재조정, (앞으로) nav2

“검은 점을 지운다”는 아래쪽 이야기다. 포즈그래프에는 검은 점이라는 것이 없다 — 스캔이 있을 뿐이다. 이 구분이 다음 절의 답을 정한다.

02지운 자리는 어디까지 사라지는가

쓰는 곳무엇을 읽나반영뜻
관리자 화면 지도map_png 된다 검은 점이 화면에서 사라진다
자동 위치 재조정같은 map_png 를 _map_grid 가 읽는다 된다 그 자리를 벽으로 치지 않는다
slam_toolbox 위치추정포즈그래프의 원본 스캔 안 된다 위치추정 정확도는 그대로
nav2 코스트맵map_server 가 읽는 .pgm 된다 실제로 지나갈 수 있게 된다

화면과 자동 위치 재조정이 같이 따라오는 이유는 둘이 같은 그림 한 장을 본다는 데 있다. _map_grid 는 화면에 내보내는 바로 그 map_png 를 받아 “벽에서 얼마나 가까운가” 점수판으로 바꾼다. 합성을 map_png 를 만드는 한 곳에서 하면 두 군데가 저절로 맞는다.

판단

slam_toolbox 에 반영되지 않는 것이 오히려 맞다.

매핑할 때 거기 있다가 지금은 치워진 파레트를 지웠다고 해서, 그때 찍힌 스캔까지 버리면 위치추정만 나빠진다. 지도에서 ‘가지 마라’ 를 빼는 일과 ‘그때 무엇이 보였나’ 를 지우는 일은 다르다. 편집은 앞의 것만 한다.

03편집은 픽셀이 아니라 월드좌표로 저장한다

픽셀 마스크월드좌표 도형 고름
저장하는 것지도와 같은 크기의 그림 한 장 지운 자리 목록 — (x, y, 반지름) [m]
이어 매핑하면지도가 넓어지며 원점이 옮겨 가 통째로 어긋난다 월드 좌표라 그 자리에 그대로 붙어 있다
되돌리기덮어썼으면 끝도형 하나씩 뺀다
원본 .pgm고쳐야 한다건드리지 않는다
나중에지우개까지금지구역·가상벽이 같은 틀에 얹힌다

증분 맵핑을 같이 만들 것이므로 픽셀 마스크는 선택지가 아니다. 이어 매핑하는 순간 지도가 넓어지면서 원점이 옮겨 가고, 지운 자리가 통째로 밀린다.

저장 형식

지도와 같은 폴더에, 지도 이름으로 묶어 둔다 — <지도이름>.edits.json. 값은 모두 미터 단위 월드좌표다.

{
  "version": 1,
  "map": "map_0826_1648",
  "shapes": [
    {"op": "erase", "kind": "circle", "x": -12.34, "y": 16.02, "r": 0.25},
    {"op": "erase", "kind": "circle", "x": -12.10, "y": 16.02, "r": 0.25},
    {"op": "erase", "kind": "rect",   "x":  -3.20, "y":  8.75,
                    "w": 1.20, "h": 0.60, "yaw": 0.35}
  ]
}

지우개를 한 번 끌면 원이 여러 개 쌓인다. 되돌리기는 그 획에서 나온 원들을 한꺼번에 빼는 것이므로, 획 단위로 묶어 둘지는 구현할 때 정한다.

op 를 따로 둔 이유는 나중에 금지구역과 가상벽이 같은 파일에 들어오기 때문이다. 이번에는 erase 하나만 쓴다.

04증분 맵핑 — 시작 자세가 전부다

필요한 것상태확인
.posegraph / .data 저장 이미 있음 mapping_save() 가 매번 저장하고 있다
모드를 받아 SLAM 을 띄우는 구조 이미 있음 slam_spawn(mode=…)
매핑 노드가 포즈그래프를 받는가 확인함 async 노드도 map_file_name·map_start_pose 를 낸다
매핑 모드로 포즈그래프를 올리는 경로 만들 것 slam_spawn 에 분기 하나

남은 일은 분기 하나뿐인데, 여기에 함정이 있다. 시작 자세를 넘기지 않으면 slam_toolbox 는 로봇이 지도의 출발점에 있다고 본다. 실제 위치가 다르면 그 차이만큼 스캔이 안 맞아 엉뚱한 곳에 새 영역을 그린다 — 8월 26일에 겪은 “지도가 대각선으로 늘어나던 문제”가 정확히 이것이었다.

그런데 이어 매핑을 시작하는 시점에는 로봇이 지도 어디에 있는지 모른다. 그래서 순서가 저절로 정해진다.

05화면에서는 이렇게 보인다

맵 수정 — 맵 화면

렉 위치 재조정 도구모음과 같은 방식으로 둔다. 확인을 누르기 전에는 아무것도 반영되지 않는다.

단추하는 일
지우개끌면 그 자리가 비워진다. 브러시 크기를 조절한다
되돌리기방금 칠한 것부터 하나씩 되돌린다
초기화편집을 전부 버리고 원본 지도로 되돌린다
확인서버에 저장한다. 이때부터 화면과 자동 위치 재조정에 반영된다
취소칠한 것을 버리고 나간다

이어서 매핑 — 매핑 화면

‘새 매핑 시작’ 옆에 ‘이어서 매핑’ 을 둔다. 위치추정 중이 아니면 눌리지 않게 하고, 왜 못 누르는지를 그 자리에 적는다 — 회색으로만 두면 고장으로 읽힌다.

07아직 정하지 않은 것

  • 편집한 지도 위에 이어 매핑하면? 지운 자리에 진짜 벽이 있으면 다시 검게 그려진다. 편집 목록은 그대로라 화면에서는 계속 지워지지만, 실제로 있는 벽을 계속 지우는 셈이 된다. 지우개는 치워진 물건 에만 쓰고, 진짜 벽을 피하는 일은 금지구역으로 다루는 것이 맞다.
  • nav2 가 지도를 어디서 받을 것인가. slam_toolbox 의 /map 을 그대로 쓰면 편집이 반영되지 않는다. map_server 에 합성한 격자지도를 물리고 slam_toolbox 는 위치추정만 하게 하는 구성이 필요하다. nav2 를 붙일 때 같이 정한다.
  • 반대 방향 — 흰 곳을 막는 ‘가상벽’. 같은 파일에 op: "wall" 로 들어가지만 이번 범위에는 넣지 않았다.
  • 지우개의 최소 단위. 브러시 반지름을 화면 배율과 무관하게 고정할지(예: 0.1 / 0.25 / 0.5 m), 화면에서 본 크기대로 할지 정하지 않았다.
