| 파일 | 내용 |
|---|---|

## 2. 기동 · 재시작 · 적용

### 2-1. 서비스

```bash
systemctl status und-amr.service        # bringup 전체 (tools/robot_service.sh)  → logs/bringup.log
systemctl status und-amr-nav2.service   # nav2 (tools/nav2_service.sh)            → logs/nav2.log
```

- 부팅하면 자동으로 뜬다. 드라이브 자동 enable 은 11/23 재부팅 때 확인했다(로그 `드라이브 자동 켜기 완료`).
- nav2_service.sh 는 위치추정이 붙을 때까지 기다린 뒤 nav2 를 띄운다. 120초 안에 활성이 안 되면 내렸다가 다시 띄운다.
- 정본은 `deploy/` 폴더에 있다(systemd 유닛, sysctl). 새 PC 에 설치할 때 그대로 복사한다.

### 2-2. 소스 변경 적용

패키지 실체는 `~/projects/UND_AMR/ros2/und_amr_bringup` 이고, `~/ros2_ws/src/und_amr_bringup` 은 그곳을 가리키는 심볼릭 링크다(11/23, colcon 은 링크를 따라간다). symlink 설치라 **이미 있는 파일을 고치면 해당 노드 재시작만으로 반영된다**. 새 파일을 추가했거나 setup.py 를 고쳤을 때만 `cd ~/ros2_ws && colcon build --symlink-install --packages-select und_amr_bringup` 을 실행한다(반드시 `~/ros2_ws` 에서).

```bash
# api_node 만 (respawn). SLAM 은 살아 있어 다음 api_node 가 이어받는다 → 위치 보존
kill -INT $(pgrep -f "^/usr/bin/python3 .*lib/und_amr_bringup/api_node")
#   준비 확인: curl -s 127.0.0.1:8090/nav/status → available true, /pois 에 충전소1
#   ⚠ 기동이 14~109초로 들쭉날쭉하다(8장)

# nav2 만 (systemd 가 15~25초 뒤 다시 띄움, SLAM·api_node 그대로)
kill -TERM $(pgrep -f "^/usr/bin/python3 /opt/ros/humble/bin/ros2 launch und_amr_bringup nav2.launch.py")
#   SIGINT 는 무시된다. sudo 필요 없음
```

- nav2 파라미터 일부는 실행 중에 `ros2 param set` 으로 바로 바뀐다(팽창, Theta* w_traversal, footprint_padding). yaml 에도 같이 써 둘 것.
- URDF 를 실행 중에 바꾸려면 robot_state_publisher 의 SetParameters **서비스**를 쓴다. `ros2 param set` 을 쓰면 xacro 문자열이 yaml 로 깨진다. camera_obstacles 는 외부값을 캐시하므로 재시작해야 반영된다.
- `pkill -f <이름>` 은 쓰지 마라. 자기 셸 명령줄까지 잡아 셸이 죽는다. `pgrep -f "^..."` 로 앞부분을 고정해 pid 를 찾는다.
- SLAM 프로세스 그룹은 `kill -INT -- -<PGID>` 로 내린다.

## 3. 주행 흐름 (지금 동작)

### 3-1. 지점(POI) 이동: `POST /pois/goto {"name":"2"}` 또는 왕복

```
 1. 위치 게이트     위치 점수 중앙값 < 0.30 이면 출발 거부 ("위치가 지도와 맞지 않습니다")
 2. 빠져나오기      POI 에 서 있으면 항상 '앞으로' 0.30m 직선 (SP_OUT_FWD_ONLY). 앞이 막혔을 때만 뒤로.
                    돌 공간이 없으면 0.3m 씩 1.5m 까지 더 나간다. 끝 0.08m 감속
 3. 출발 회전       경로 0.6m 앞 점 기준. 25° 안이면 서지 않고 곡선 출발.
                    렉 없음(리프트 bottom) 0.90 rad/s, 렉 있으면 0.50. 회전 전에 쓸고 갈 영역 검사
                    출발 비틀림 미리 돌림 두 번 (SP_KICK_W / SP_KICK2_W 0.04)
 4. 서서히 출발     0.04 m/s 로 시작해 10cm + 40cm 에 걸쳐 설정 속도까지 (웹 '출발 설정', /nav/depart_params)
 5. nav2            Theta* 직선 경로 + RPP. 주행 속도 설정 0.5 m/s (~/ros2_ws/und_amr_settings.json)
 6. 접근 감속       앞 자리(POI 앞 0.6m) 0.85m 전부터 0.20 m/s 까지 S자 감속 (SP_APPR_*)
 7. 넘겨받기        앞 자리 0.35m 안·방향/좌우 조건이면 nav2 를 끊고 달리며 직선 진입으로 넘긴다
                    넘겨받은 직선: 감속 0.25 m/s², 회전 7°/s, 각가속 0.25, 0.3초 앞 예측 (휘청 방지)
 8. 직선 진입       POI 점을 겨누며 0.20 m/s. 축을 map→odom 으로 매 주기 다시 맞춤 (SP_REANCHOR)
 9. 도착 회전       방향만 제자리 회전. 렉 없으면 0.70 rad/s. 자리 맞추기(기어가기·재진입)는 하지 않는다
```

- 좁은 POI(웹 POI 목록의 [좁은 곳])는 NP_* 경로를 탄다. 축 위 1m 앞 자리에 서고 0.10 m/s 로 곧게 들어가며, 안에서 돌 공간을 미리 판단한다. 지도 자동 판정은 11/17 에 껐다.
- 도착 정밀도: 지도 기준 최대 약 12mm. 실제(스캔 ICP) 흩어짐은 POI 1 ±6/±4mm, POI 2 ±4/±5mm 이다.

### 3-2. 왕복: `POST /route/start {"a":"1","b":"2","repeat":0,"dwell":3}`

- repeat 0 은 무한이다. A 로 먼저 간다. 실패하면 1회 재시도한다. 정지·수동·다른 목표·렉 작업이 들어오면 멈춘다.
- 끝점에 충전소를 줄 수 있다. 그 경우 도킹으로 도착하고 리프트 없이 3초 뒤 출발한다. `lift:false` 로 리프트를 생략할 수 있다.

### 3-3. 충전소 도킹: `POST /charger/dock`

```
대기 자리(0.8m)까지 nav2 → 도착 순간 POI 기준 중간 지점(0.45m)으로 한 번에 등 돌리기(0.7 rad/s)
→ 중간까지 후진하며 V 홈을 계속 재서 축에 올라탐 (CD_AXIS_BACK)
→ 서서 재측정 → 3° 넘으면 축 방향 회전 → 마지막 후진은 방향 고정, 0.06 m/s, 접촉 4cm 전부터 0.04
→ 충전 판정: 서 있을 때 BMS 전류 > -0.6A, 또는 SOC ≥ 90% 면 접촉 위치 도달로 완료
```

- 라이다 인식 치우침(거리별 8~15mm)은 `CD_BIAS_*` 보정표로 지운다(11/18 실측).
- 결과(11/18): 10/10 성공. POI1 출발→도킹 완료 44.4초, 끝 좌우 -0~-2mm, 방향 ≤0.5°.
- 기동 때 충전소에 붙어 있으면 충전소 POI 자세로 위치를 바로잡는다(`_boot_dock_check`).
- 배터리는 28.85V(96%)에서 충전이 멈춘다. 소프트웨어는 충전을 끊지 않는다. 충전기 전압 또는 경로 낙차 문제로 HW 확인 대기 중이다.

### 3-4. 렉 작업: `POST /job/start {"poi":"렉1"}`

- 9/22 문서 3장의 상태기계 골격은 같다. 그 뒤 이렇게 바뀌었다.
  - 렉 축 선 추종 조향(9/28): K_LAT 1.90, K_YAW 0.70.

## 10. 안전 ★

9/22 문서 7장(라이다 거리 ≠ 차체 여유, 실제로 저지른 실수)은 그대로 유효하다. 차체 치수만 새로 바뀌었다.

```
차체 외곽     ±0.437 x ±0.165 m (구동축 기준)
제자리 회전 반경  sqrt(0.437² + 0.165²) ≈ 0.467 m (모서리가 깎여 실제는 조금 작다)
라이다         구동축 위가 아니다 → 반드시 /scan(합친 것, frame laser = 구동축 위) 기준으로 계산
```

- 직접 `/cmd_vel_noradius` 로 돌리는 스크립트는 collision_monitor 를 거치지 않는다. 주변을 비우고 사람이 보고 있을 때만 쓴다.
- 축1 알람이 나면 로봇은 서고 잠긴다. 복구는 `clear_errors` 후 enable 이다. **원인(HW)을 모른 채 반복하지 마라.**

### 11-3. 휘청·흔들림을 잴 때

- 전과 후를 **같은 경로**로 비교한다: 1↔2 3회 + 1↔충전소1 3회.
- 자이로는 0.3~3Hz 대역만 본다. 바퀴 방향과 지도 좌우도 함께 본다.
- 시작 자리가 이미 POI 1 근처면 큰 회전이 섞인다. 그 회차는 빼고 본다.

### 11-4. 주요 API

```
GET  /nav/status          available, state, msg, loc_mon, blocked_s
GET  /chassis/pose        map/odom 자세 (map null = TF 미준비)
GET  /mapping/status      active_map, 위치추정 상태
GET  /pois, POST /pois, POST /pois/goto {"name":..}
POST /route/start {"a","b","repeat","dwell","lift"} · /route/cancel · GET /route/status
POST /charger/dock · /charger/cancel · GET /charger/status
POST /job/start {"poi"} · /job/exit · /job/cancel · GET /job/status
POST /localization/manual {"x","y","yaw"} · /localization/auto · /localization/release
GET/POST /nav/depart_params   출발 서서히 구간 실시간 조정
POST /nav/speed · /services/estop · /services/stop
GET  /battery-state · /battery-history?hours=
```

리프트 API(`/lift/up` 등)는 사람이 로봇을 보고 있을 때만 호출한다.
