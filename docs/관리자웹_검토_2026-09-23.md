# 관리자 웹 검토 — 2026-09-23

## 범위와 검증 방법

`ros2_ws/src/und_amr_bringup/und_amr_bringup/web_ui.py`의 화면·입력·폴링과
`api_node.py`의 HTTP 처리·주행·도킹·정지 경로를 대조했다.
차체 크기는 `urdf/amr.urdf.xacro`, 즉시 정지는 `base_node.py`도 확인했다.

실제 로봇 API에 접속하지 않았다. Chromium에서 **모든 요청을 가짜 응답으로
처리**하여 16개 메뉴를 열고 UI 오류·정지 요청·통신 실패 표시를 확인했다.
서버 재현에서는 노드를 생성하지 않고 기존 메서드를 호출하되, 발행기·액션 클라이언트를
메모리 기록용 대역으로 바꿨다. 서비스 재시작·주행·운용 소스 수정은 하지 않았다.
현재 배포된 화면과 실물 정지 성능을 검증한 결과는 아니다.

## 구조와 주요 조작 흐름

단일 Python 문자열 `PAGE` 안에 HTML/CSS/JavaScript가 들어 있고,
`api_node.Handler`가 `/`에서 제공한다. 별도 프런트엔드 빌드는 없다.
좌측 메뉴는 hash로 전환하며 모든 패널이 DOM에 남는다.

| 영역 | 주요 기능·연결 |
|---|---|
| 대시보드 | 지도·위치·라이다·경로, 자동/수동, 모터 사용·정지·축 해제, 조이스틱, 도킹 |
| 모터·배터리 | `/chassis/status`, `/battery-state` |
| 라이다·카메라 | `/scan`, `/camera/info`, MJPEG, 렉 다리 검출 오버레이, 장치 재시작 |
| 맵 | 저장 지도 목록·미리보기·메모·적용·삭제 |
| 매핑 | 시작·일시정지·저장·종료·이어 그리기, 지우개·가상벽·금지구역, POI 등록 |
| 지도 이동 | 누르고 끌어 도착 방향 지정 → `/nav/goto`, 이동 중 `/nav/status` |
| 도킹 | POI 선택 → `/job/start`, `/job/status`, 전용 중단 `/job/cancel` |
| 위치 재조정 | 지도상 위치/각도 지정 또는 자동 추정 → 초기 자세 관련 API |
| 대차 실측 | `/carts/measure`, `/carts/register`, `/carts/unregister` |
| 네트워크 | WiFi 목록·접속·고정 IP·핫스팟 설정 |
| 노드·토픽 | `/nodes`, `/topics` |
| 로그·서비스·장비 정보 | 화면은 있으나 아래 함수 누락으로 일부 로딩 실패 |
| 이동 작업·파라미터 | 명시적인 미구현 패널. 지도 이동·도킹 기능은 다른 화면에 존재 |

상태·도킹은 500ms, 스캔은 200ms, 렉 검출은 400ms, 지도는 1500ms,
POI 목록은 2000ms 간격으로 폴링한다. 수동 명령은 150ms마다 전송하며,
서버에는 수동 명령 0.30초 만료, 모터에는 cmd_vel 0.5초 만료가 있다.
이 타임아웃은 다른 주행 코드가 새 명령을 계속 내보내는 문제를 해결하지 않는다.

## 발견 사항 — 우선순위 순

### P1. 정지·비상정지·수동 전환이 주행 명령의 모든 발생원을 막지 않는다

- `web_ui.py:878`의 대시보드 정지는 `/services/stop`만 호출한다.
- `api_node.py:5558`의 `stop_now()`는 수동 명령을 지우고 0을 발행하며 모터 즉시 정지를
  요청하지만, 도킹 타이머·Nav2 목표·도착 후 방향 보정 타이머를 취소하지 않는다.
- `api_node.py:4765` 부근 `_turn_tick()`은 `estop`과 제어 모드를 확인하지 않는다.
- `/services/estop` 역시 플래그 변경과 `stop_now()`만 수행한다(`api_node.py:5833`).
  도킹 타이머는 estop을 검사하지만 `_job_fail()`은 진행 중 Nav2 목표를 취소하지 않는다.
- `/chassis/status`의 수동 전환도 `stop_now()`만 호출하며, `_job_tick()`은 수동 전환을
  검사하지 않는다. 도킹과 수동 조작의 명령이 겹칠 수 있다.
- `nav_goto()`(`api_node.py:4586`)는 비상정지·수동 모드·진행 중 도킹을 검사하지 않는다.

메모리 대역으로 실제 메서드를 재현한 결과:

```text
stop_now() → _turn_tick():  (v=0,w=0) 다음 (v=0,w=+0.35)
estop=True에서도 동일
estop=True + control_mode=manual에서 nav_goto(): True, 목표 전송 1회
```

추가로 브라우저 `stopNow()`는 조이스틱 반복 타이머를 지우지 않는다.
수동 반복 송신이 켜진 상태에서 호출하면 `/services/stop` 다음에
`/chassis/twist {linear:0.2, angular:0}`가 다시 발행됐다(모두 모의 요청).
`stopDrive()`에는 타이머 해제가 있으나 일반 정지 버튼은 이 함수를 사용하지 않는다.

개선 방향: 정지/비상정지/모드 전환 시 해당 주행의 타이머·대기 중 액션·활성 목표를
종료하고, 모든 명령 발생 지점에서 운용 상태를 검사한다. 새 목표가 아직 수락되지 않은
`sending` 단계의 취소도 포함해야 한다. 브라우저 정지는 수동 반복 송신도 해제해야 한다.

### P1. 지도 목표 드래그 취소가 이동 시작으로 처리된다

`web_ui.py:2116` 부근의 공용 `end()`를 `pointerup`과 `pointercancel`에 같이 연결했다.
`goal.dragging`이면 두 이벤트 모두 `goalUp()` → `/nav/goto`를 호출한다.
따라서 브라우저가 터치를 취소한 경우에도 이동 시작으로 처리하는 경로가 있다.
이는 소스에서 확인했으며 해당 이벤트의 실기기 재현은 하지 않았다.
취소 이벤트는 이동 목표 제출 없이 드래그 상태만 해제해야 한다.

### P2. 로그·서비스·장비 정보 메뉴의 함수가 누락됐다

호출만 있고 정의가 없는 함수:

- `loadLog` (`web_ui.py:2894`) — 로그 화면 주기 갱신
- `logLevel` (`:731` 부근) — 로그 수준 버튼
- `loadSvc` (`:855`) — 서비스 화면 목록
- `loadDev` (`:852`) — 장비 정보

모의 브라우저에서 해당 메뉴/버튼을 누르면 각각 `ReferenceError: ... is not defined`가
발생했다. 기능 메뉴는 구현됨 표시인데 내용은 로딩되지 않는다. 서비스의 개별 버튼은
별도 함수이므로 목록 로딩 실패와 구분해야 한다.

### P2. 지도에 그리는 로봇 크기가 현재 SLIM 차체와 다르다

`web_ui.py:755`: `ROBOT={len:0.80, wid:0.27, front:0.38}`.
현재 URDF는 길이 0.870m, 앞끝까지 0.435m다.
그 결과 화면의 앞끝은 55mm, 뒤끝은 15mm 짧게 표현된다.
화면 크기를 근거로 작은 렉과의 간격을 판단하면 여유를 실제보다 크게 보게 된다.
표시 좌표와 실제 기하를 같은 원천에서 가져오는 편이 좋다.

### P2. 도킹 시작 실패 이유와 통신 단절이 화면에서 사라진다

`poiJobStart()`가 쓴 시작 실패 이유를 500ms 주기의 `poiJobPoll()`이 덮어쓴다.
서버 작업 상태가 idle이면 `dockJob`을 `렉을 고르세요`로 바꾼다.
모의 `/job/start` 거절 뒤 해당 메시지가 다음 poll에서 사라지는 것을 재현했다.

또한 `/job/status`만 실패하면 빈 `catch`로 끝난다. 모의 네트워크 실패 후에도
`poiJob.state=entering`, 화면 `후진 진입 중`이 그대로 남았다.
최근 상태 수신 시각·단절 표시와 시작 요청 실패 메시지의 수명이 필요하다.

### P2. POI 등록 안내가 서로 모순된다

- 매핑 등록 안내: `렉 중심에 로봇을 세우고 등록` (`web_ui.py:2569` 부근)
- 도킹 목록이 비었을 때: `대차 앞에 세우고 POI로 등록` (`:2699` 부근)

POI는 도킹 완료 자세다. 두 번째 안내대로 대기 위치를 저장하면 서버는 그 지점을
대차 중심으로 해석하므로 접근·진입 목표가 잘못 잡힌다. 빈 목록 안내를 브라우저에서도 확인했다.

### P2. 모바일 대시보드가 한 열로 바뀌지 않는다

`#pane-dash.sel`의 2열 규칙이 미디어 쿼리 `.wrap.sel`보다 우선한다.
390px viewport에서 열 너비가 `59.9844px 280px`로 남아 지도 영역이 약 60px로 찌그러졌다.
실제 스크린샷으로 확인했다. 작은 화면에서는 대시보드 자체의 열 정의도 재지정해야 한다.

### 추가 정리 사항

- 수동 모드의 W/A/S/D·방향키가 전역으로 등록되어 로그 화면에서도 수동 지령을 보낸다.
  모의 브라우저에서 로그 화면 W 입력 후 joy.active와 반복 타이머가 켜졌다.
  화면 전환 시 조작 해제 및 운전 화면 범위로 단축키 제한을 검토한다.
- 서비스 안내의 `알람 클리어 미구현`은 실제 `/services/clear_errors` →
  `base_node._srv_clear()` 구현과 다르다.
- 주행속도 슬라이더 초기값은 0.25인데 서버 값 반영은 이동 상태 poll에서만 호출된다.
  처음 대시보드를 열었을 때 저장된 실제 값과 다르게 표시될 수 있다.
- 렉·지도 이름을 HTML/onclick에 직접 넣는 부분이 있다(`ccLoad`, `loadMaps`).
  특수문자 처리를 일관되게 하지 않아 정상 이름에서도 UI가 깨질 수 있다.
  이번 검토에서는 삽입 공격을 실행하지 않았다.
